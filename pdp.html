Pattern · Product Detail Page

PDP

Product Detail Page — a página onde o utilizador decide a compra. Documentada por blocos individuais para facilitar consulta, manutenção e implementação em CMS.

Como ler esta página A secção Anatomia mostra o screenshot completo da PDP com cada bloco numerado. As secções seguintes documentam cada bloco isoladamente: o que faz, quando aparece, que componentes usa e o HTML/CSS pronto a copiar.

Layout

Estrutura

Desktop: top bar full-width → grid 2 colunas (galeria + buy block) → tabs full-width. Largura máxima 1920px centrada.

BreakpointGridNotas
≥ 1024px2 colunas · galeria (50%) + info (50%)Top bar e tabs full-width. Max-width 1920px.
768–1023px2 colunas · galeria (45%) + info (55%)Galeria mantém grid 2×2.
< 768pxStack verticalOrdem: galeria → meta → título → preço → ADICIONAR sticky → resto.

UX rationale

Porquê esta estrutura

Top bar antes do título

Part-Number e EAN são procurados por utilizadores técnicos. Garantia gera confiança imediata. Trustpilot mostra prova social no primeiro contacto visual. Tudo isto reforça credibilidade antes do utilizador decidir continuar a explorar.

Botão "ADICIONAR" em uppercase

Padrão consistente do site PCDIGA. Uppercase + tamanho grande + cor brand = ação principal inequívoca. Ocupa toda a largura ao lado do qty stepper, eliminando ambiguidade sobre o que fazer.

PCDIGACare entre CTA e info secundária

Posição estratégica: depois do utilizador ver preço e stock, antes de scroll para mais detalhes. Maximiza atenção para o upsell de protecção sem distrair o CTA primário.

Características sempre visíveis

3-6 bullets de venda acima do fold sem precisar de abrir as tabs. O utilizador valida a decisão sem competir com o CTA. Tabs ficam para quem quer aprofundar.

Favoritos / Comparar sob a galeria

Ações secundárias afastadas do CTA principal. Posição visual lógica (relacionadas com a imagem do produto) sem competir com "ADICIONAR".

Tabs com nomes específicos PCDIGA

"Detalhes do Produto" (marketing copy + features) vs "Informações Técnicas" (specs frias) vs "Avaliações" (Trustpilot). Linguagem que o utilizador português entende, em vez de "Specs/Reviews/Info" mais genéricos.

Do's & Don'ts

✓ Faz

"ADICIONAR" como texto do CTA (uppercase). Padrão estabelecido do PCDIGA.

✗ Evita

"Adicionar ao carrinho" longo ou "Comprar agora" inconsistente com o resto do site.

✓ Faz

PCDIGACare addons opt-in (nenhum radio seleccionado por defeito). Utilizador escolhe ativamente.

✗ Evita

PCDIGACare pré-seleccionado. Dark pattern — utilizador pode comprar sem perceber.

✓ Faz

Datas da promoção sempre visíveis quando há PVPR.

✗ Evita

PVPR sem datas — utilizador não sabe quando termina a promo.

✓ Faz

Características Principais sempre visíveis (não dentro de colapsável).

✗ Evita

Esconder características num colapsável "Ver mais" — utilizador precisa de validar a compra rapidamente.

Mobile

PDP em mobile

Stack vertical. Ordem dos blocos: breadcrumbs → top bar (collapse) → galeria → favoritos/comparar → título → preço → portes → stock → ADICIONAR → PCDIGACare → colapsáveis → características → tabs.

ADICIONAR sticky em mobile Quando o utilizador faz scroll para baixo, o CTA "ADICIONAR" + qty stepper fica fixo no fundo do viewport. Garante decisão de compra sempre acessível, mesmo em produtos com muita info técnica.
