Pattern · Shopping cart

Cart

O carrinho é onde o utilizador pára para rever a decisão antes de pagar. Documentado em dois formatos: mini-cart (dropdown no header, feedback imediato após "ADICIONAR") e cart full-page (página dedicada com totais, promo code e checkout).

Princípio central O carrinho não é uma etapa decorativa. É a última oportunidade de remover fricção antes do checkout — preço claro, portes visíveis, totais sem surpresas, CTA único.
Anatomia

Dois formatos

O carrinho aparece em dois sítios. Mini-cart é confirmação rápida após adicionar. Full-page é o passo formal antes do checkout.

FormatoQuando apareceObjectivo
Mini-cartHover/click no ícone de carrinho. Auto-abre 3s após "ADICIONAR".Confirmar a acção. Mostrar resumo. Encaminhar para checkout sem mudar de página.
Cart full-pageURL /carrinho. Clique em "Ver carrinho" ou ícone.Rever antes do checkout. Alterar quantidades, aplicar promo, escolher método de envio.
Layout

Estrutura

Mini-cart: dropdown 380px posicionado abaixo do ícone. Full-page: grid 2 colunas — linhas à esquerda (66%), resumo à direita sticky (34%).

Porquê

Decisões UX

Mini-cart auto-abre 3s após "ADICIONAR"

Confirma a acção sem mudar de página. 3s é suficiente para registar visualmente sem interromper navegação. Se o utilizador continua a comprar, fecha sozinho.

"Remover" via Modal de confirmação

Remover um produto é destrutivo — clique acidental pode frustrar. Usar o Modal "Remover produto do carrinho" com CANCELAR + REMOVER PRODUTO confirma a intenção sem ser pesado.

Promo code colapsado por defeito

Se aparece aberto, o utilizador que não tem código sente que está a perder algo (FOMO). Colapsado, está disponível para quem precisa sem distrair os outros.

Barra de portes grátis sempre que aplicável

Motiva a adicionar mais itens. Mostra quanto falta (concreto) em vez de "Falta pouco" (vago). Quando atingido, confirmação verde imediata.

Resumo sticky no scroll (desktop)

Em carrinhos longos, o total + CTA não pode desaparecer. Sticky no lado direito mantém a decisão visível enquanto o utilizador revê os itens.

CTA único e claro: "FINALIZAR ENCOMENDA"

Uma só acção primária. "Continuar a comprar" como link secundário discreto. Pagamento ainda não, é só na próxima página (Checkout).

Usage

Do's & Don'ts

✓ Faz

Portes visíveis ANTES do checkout. "Portes: Grátis" ou "Portes: 4,90 €" no resumo.

✗ Evita

"Portes calculados no checkout" sem indicação. Surpresa de preço = abandono.

✓ Faz

Confirmar remoção via Modal. Acção destrutiva merece um clique a mais.

✗ Evita

Remover sem confirmação. Utilizador clica no X, perde produto, fica frustrado.

✓ Faz

Promo code colapsado por defeito. Quem tem, abre. Quem não tem, ignora.

✗ Evita

Promo code aberto e bem visível. Cria FOMO em quem não tem código e sente que está a pagar mais.

✓ Faz

CTA único: "FINALIZAR ENCOMENDA" primary. "Continuar a comprar" como link discreto.

✗ Evita

Dois CTAs primary lado a lado. Utilizador hesita, não decide.

✓ Faz

Total IVA incluído. Mostrar "IVA incluído" abaixo do total.

✗ Evita

IVA escondido até ao checkout. Em PT é norma legal mostrar preços com IVA — também é norma UX.

Mobile

Cart em mobile

Mini-cart passa a drawer full-width que entra pela direita. Cart full-page faz stack vertical: linhas → progresso de portes → resumo → CTA.

FINALIZAR sticky no fundo Em mobile, o CTA "FINALIZAR ENCOMENDA" fica fixo no fundo do viewport durante o scroll dos itens. Total visível ao lado do CTA (ex: "1 349,73 € · FINALIZAR"). Garante que o utilizador nunca tem de fazer scroll para finalizar.

Acessibilidade

Mini-cart dialogrole="dialog" + aria-label="Resumo do carrinho". Focus trap quando aberto. Esc fecha.
Trigger badgearia-label dinâmico: "Abrir carrinho · N produtos". Screen reader anuncia a contagem.
