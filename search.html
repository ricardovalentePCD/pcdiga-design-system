Pattern · Search

Search

A pesquisa é o atalho do utilizador que já sabe o que quer. Documentada em três zonas: search bar no header, sugestões live à medida que escreve, e página de resultados em /pesquisa.

Princípio central Bons resultados em menos cliques. Sugestões úteis enquanto escreve, resultados precisos e refinamento simples quando há demasiados.
Anatomia

Três zonas

A pesquisa percorre três momentos na jornada. Cada um tem objectivo distinto.

ZonaQuando apareceObjectivo
Search barSempre visível no header. Foco automático em /pesquisa.Ponto de entrada. Sinal claro de "começa aqui".
Sugestões liveDropdown a partir de 2 caracteres. Debounce 200ms.Atalho — query, produto, categoria ou marca sem submeter.
Página de resultadosURL /pesquisa?q=.... Após submit ou enter.Lista completa, filtrável. Igual a PLP mas com contexto da query.

5

Filtros e grid de resultados

Reutiliza integralmente os blocos da PLP: toolbar, filtros sidebar, grid de product cards, paginação. Single source of truth — manter consistência entre PLP e Search.

Reaproveitamento Não duplicar componentes. Filtros, toolbar, product card, grid e paginação vivem na PLP. O Search só adiciona o header de resultados por cima.

Porquê

Decisões UX

Search bar sempre visível no header

A pesquisa é o atalho do utilizador que já tem intenção. Esconder atrás de um ícone é fricção — bar visível baixa o tempo até ao primeiro resultado.

Sugestões a partir de 2 caracteres

Com 1 caracter ainda não há sinal útil — sugestões com "x" são ruído. 2 é o mínimo para começar a discriminar.

Debounce de 200ms

Equilíbrio entre instantâneo e eficiente. Menos de 150ms dispara dezenas de pedidos enquanto o utilizador escreve. Mais de 300ms começa a parecer lento.

Mistura tipos de sugestão

Queries (atalho rápido), produtos (resultado directo), categorias e marcas (refinamento). O utilizador escolhe a granularidade que prefere — não força um único caminho.

"Did you mean" só com fuzzy match

Não mostrar sempre. Só quando o algoritmo tem confiança alta de typo. Sugestão errada é pior do que ausência de sugestão.

No-results nunca é dead-end

Sem resultados continua a ser uma página útil. Sugestões populares + CTAs claros mantêm a jornada. Mensagem em humano — "Verifica a ortografia" — não código de erro.

Histórico via localStorage

Recentes sem login obrigatório. Privacidade por defeito — só no browser do utilizador. Pode ser limpo no perfil.

Usage

Do's & Don'ts

✓ Faz

Placeholder específico: "Procura por produto, marca ou categoria". Sugere o que se pode procurar.

✗ Evita

"Pesquisar..." genérico. Não dá pista do que pode ser procurado.

✓ Faz

Highlight do termo da query no resultado (a bold). Confirma visualmente o match.

✗ Evita

Sugestões sem highlight. Utilizador tem de procurar o termo dentro do texto.

✓ Faz

Sem resultados → sugestões populares + CTA. Mantém a jornada activa.

✗ Evita

"Sem resultados." página em branco. É um dead-end frustrante.

✓ Faz

Navegação por teclado ↑↓ + Enter. Esc fecha o dropdown.

✗ Evita

Sugestões só com mouse. Power users e acessibilidade ficam fora.

✓ Faz

URL com query (?q=xiaomi). Partilhável e bookmarkable.

✗ Evita

Estado interno só. Partilhar link não reproduz a mesma pesquisa.

Mobile

Search em mobile

Search bar passa a ícone no header. Tocar abre overlay full-screen com input no topo + sugestões abaixo. Botão "Cancelar" no canto direito para fechar.

Auto-focus no input Quando o overlay abre, o input recebe focus automaticamente e o teclado mobile abre. Reduz cliques — utilizador pode começar a escrever logo.

Acessibilidade

Acessibilidade

Inputtype="search" + aria-label="Pesquisar". Mobile: teclado com botão "Procurar".
ComboboxDropdown anunciado com role="listbox". Bar com aria-expanded e aria-controls a apontar ao dropdown.
SugestõesCada item role="option" + aria-selected="true" no item activo.
Teclado↑↓ navega, Enter selecciona, Esc fecha. Tab sai do dropdown sem o fechar.
Botão limpararia-label="Limpar pesquisa". Foco volta ao input após clicar.
Contagem resultadosAnunciada via aria-live="polite": "47 produtos encontrados para xiaomi 15t".
No resultsHeading h2 com a mensagem. Não usar só ícone — screen readers precisam de texto.
